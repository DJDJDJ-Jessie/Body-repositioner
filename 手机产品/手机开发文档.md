# 身体复位器手机版开发文档

更新日期：2026-08-01

## 1. 当前交付形态

当前交付是一个无构建依赖的移动网页 PWA 原型：

- 页面：index.html
- 逻辑：app.js
- 样式：styles.css
- 安装清单：manifest.webmanifest
- 离线缓存：sw.js
- 图标：icon.svg

这样做的原因是先验证产品闭环，不把验证成本绑定到 App Store、Google Play、账号、服务端和原生打包。

## 2. 运行方式

### 直接预览

可以直接用浏览器打开 index.html 查看界面和计时器。

### 启用 PWA 和离线缓存

PWA 的 Service Worker 需要 HTTP 或 HTTPS 环境。进入 body-reset-mobile 目录后，用任意静态文件服务器启动，例如：

    python -m http.server 4173

然后打开：

    http://localhost:4173

在手机上体验时，把静态文件放到局域网可访问的地址，手机和电脑接入同一网络后打开该地址即可。

## 3. 目录结构

    body-reset-mobile/
      index.html
      app.js
      styles.css
      manifest.webmanifest
      sw.js
      icon.svg

原型没有依赖前端框架，方便后续迁移到 Vue、React、Capacitor 或原生工程。已有桌面版仍然保留在上级目录的 body-reset-electron 中，两者不互相覆盖。

## 4. 状态与数据模型

本地存储键：

    body-reset-mobile-state-v1

状态包括：

- view：当前导航页面。
- settings.focusMinutes：专注时长。
- settings.notifications：是否允许通知。
- focus.mode：idle、running 或 paused。
- focus.remainingMs：专注剩余时间。
- focus.totalMs：当前一轮专注总时长。
- history：每日专注分钟数、复位分钟数和完成次数。

日期使用浏览器本地时区生成 YYYY-MM-DD。统计先保存在 localStorage，后续可替换成 IndexedDB，并加入导出功能。

## 5. 核心交互

### 专注计时

1. 用户点击开始专注。
2. app.js 每秒扣减剩余时间。
3. 每 10 秒将状态写入本地存储，避免刷新后完全丢失。
4. 专注结束后打开默认的颈肩复位。
5. 复位完成后，增加当天的完成次数和复位分钟数。

### 复位计时

1. 用户从今日页或复位库选择一条路径。
2. 复位页进入全屏式深色体验。
3. 默认路径使用动作阶段卡和呼吸灯作为内容占位。
4. 导入视频后，复位页使用 video 元素播放用户本地视频。
5. 点击完成后才写入身体账本。

### 本地视频

用户选择视频后，使用 URL.createObjectURL 创建当前设备的临时播放地址。原型不上传文件，也不把视频二进制写入 localStorage。

因此需要明确：

- 刷新或关闭页面后，临时视频地址会失效。
- 生产版应使用 IndexedDB、File System Access API 或原生文件沙盒。
- 不应把大视频直接存入 localStorage。

## 6. PWA 能力与限制

当前已加入：

- manifest.webmanifest。
- Service Worker 静态资源缓存。
- standalone 显示模式。
- 安全区域适配。
- 触摸友好的底部导航和按钮。
- reduced-motion 适配。

当前不能承诺：

- 浏览器被系统完全杀死后仍然百分之百准时通知。
- 像桌面 Electron 一样强制打断其他 App。
- 在锁屏、低电量或系统省电策略下持续运行秒级计时器。

这些能力需要原生通知和后台任务，并且要按 iOS、Android 分别设计。

## 7. 从原型到生产的技术路线

### 阶段 A：验证闭环

- 让 3–5 名真实用户连续使用 7 天。
- 观察他们是否真的完成复位，而不是只打开通知。
- 记录跳过原因：忙、动作不合适、时长太长、提醒太弱或播放失败。

### 阶段 B：补齐内容与可靠性

- 将动作内容拆成部位、场景、时长、难度和禁忌标签。
- 把本地视频改为 IndexedDB 或应用沙盒。
- 增加“稍后提醒”和“今天不再提醒”。
- 增加播放失败、无权限、无视频和通知被拒绝的清晰状态。

### 阶段 C：原生封装

建议先用 Capacitor 验证原生能力，原因是可以最大程度复用当前移动网页：

- Web UI 继续复用。
- 本地通知使用原生插件。
- 视频文件使用应用沙盒。
- 需要时再把计时、通知和健康数据迁移到原生层。

如果后续需要更复杂的后台计时、健康数据和系统级交互，再评估 React Native 或完全原生开发。

## 8. 测试清单

### 功能

- 首次打开可以看到今日页。
- 开始、暂停、继续专注正常。
- 修改专注时长后，下一轮倒计时使用新值。
- 立即复位可以进入复位页。
- 复位暂停、继续和完成正常。
- 完成后今日次数、复位时长和账本同步增加。
- 刷新页面后本地统计仍保留。
- 上传视频可以播放，关闭后不会上传。
- 通知权限拒绝时有明确提示。

### 移动端

- 320px 宽屏幕无横向滚动。
- iPhone 刘海和底部手势区域不遮挡内容。
- 竖屏下按钮可单手点击。
- 文字不截断。
- 系统开启减少动态效果时，呼吸灯仍然可用但不持续动画。
- 返回键、刷新和离线打开不会导致白屏。

### 内容安全

- 不写诊断或治疗承诺。
- 提醒用户不在疼痛或眩晕时强行完成动作。
- 导入视频的文件名需要转义，避免插入页面结构。

## 9. 发布前待办

- 选定一套自有或有授权的复位视频。
- 增加隐私政策和服务条款页面。
- 对通知、视频、统计数据做数据最小化说明。
- 验证 Safari、Chrome Android、微信内置浏览器的打开行为。
- 评估是否需要域名和 HTTPS。
- 通过真实用户测试后再决定是否进入原生应用开发。
